# 결제 기록장 (크롬 확장프로그램)

결제하거나 카드를 등록할 때마다 **어느 사이트에서 / 구독인지 일회성인지 / 얼마인지 / 어떤 카드로**를 자동으로 기록하고, 매달 나가는 구독료를 한눈에 보여줍니다.

**AWS · Azure · OpenAI** 계정을 연결하면 이번 달 사용료·월말 예상·지난달을 매일 아침 가져와 원화로 합쳐 보여줍니다.

## 설치

1. 크롬 주소창에 `chrome://extensions` 입력
2. 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** → 이 폴더(`payment-tracker`) 선택
4. 툴바 퍼즐 아이콘에서 "결제 기록장"을 고정

기록되면 아이콘에 잠깐 `✓` 배지가 뜹니다. 팝업에서 요약을 보고, **전체 대시보드 열기**로 전체 목록·수정·CSV 내보내기를 할 수 있습니다.

## 추가하기 · 내 카드

- 대시보드의 **추가**를 누르면 서버·클라우드 / AI / 개발 도구 / 업무 도구 / 생활 구독 목록이 떠요. 한글로 검색해도 돼요(넷플, 커서…).
- AWS·Azure·OpenAI·Cloudflare·GitHub·Vercel은 사용료 자동 연결 화면으로, 나머지는 요금제가 채워진 기록 양식으로 이어져요. 연결이 안 되는 계정은 연결 화면의 "요금제로 직접 기록"을 쓰면 돼요.
- 요금제 가격은 `src/lib/catalog.js`의 `PRICES_AS_OF` 기준 참고가예요. 가격이 바뀌면 이 파일만 고치면 돼요.
- **내 카드**: 별명·종류·끝 4자리만 등록해요(카드번호 전체·CVC·유효기간은 받지 않아요). 기록할 때 드롭다운으로 고르고, 카드별 월 합계가 보여요.
- 달러 구독을 원화로 합치려고 대시보드를 열 때 `open.er-api.com`에서 원/달러 환율을 받아요(12시간에 한 번, 실패하면 10분 뒤 재시도). 이 요청에는 기록·카드 정보가 실리지 않아요.

## 서버·API 사용료 (AWS · Azure · OpenAI · Cloudflare · GitHub · Vercel)

대시보드 **연결 추가**에서 서비스를 고르고 화면 안내를 따라가면 됩니다. 저장 전에 실제로 한 번 불러 보고, 틀리면 이유를 알려줍니다.

| 서비스 | 연결 방법 | 필요한 권한 | 비용 |
|---|---|---|---|
| AWS | 읽기 전용 IAM 사용자의 액세스 키 붙여넣기 | `ce:GetCostAndUsage` 하나 | 조회 1번 $0.01 → 한 달 약 $0.30 |
| Azure | Microsoft 로그인 버튼 | 구독의 Cost Management 읽기 권한자 | 없음 |
| OpenAI | 관리자 키(`sk-admin-`) 붙여넣기 | 조직 Owner가 만든 키 | 없음 |
| Cloudflare | API 토큰 붙여넣기(계정 ID는 선택) | Account · Billing · Read | 없음 |
| GitHub | Fine-grained 토큰 붙여넣기(조직은 선택) | Plan: Read-only (조직은 관리자) | 없음 |
| Vercel | 토큰 붙여넣기(팀은 선택, 비우면 모든 팀) | 팀에서 청구를 볼 수 있는 역할. 읽기 전용 토큰은 없음 | 없음 |

- **Cloudflare**는 계정 청구 내역(`/accounts/{id}/billing/history`)을 읽어요. 한 달에 한 번 청구되는 구조라 월말 예상은 지난달·이번 달 청구액 중 큰 값이에요.
- **GitHub**는 청구 사용량 보고서(`/settings/billing/usage`)의 `netAmount`를 더해요. GitHub의 새 청구 플랫폼(enhanced billing)을 쓰는 계정·조직만 돼요.
- **Vercel**은 청구 요금(`/v1/billing/charges`, FOCUS JSONL)의 `BilledCost`를 더해요. 요금제 결제·크레딧·조정은 월말 예상에서 늘려 잡지 않아요.
- 세 서비스는 공식 문서 형식대로 만든 가짜 응답으로만 검증했어요(`e2e/providers.e2e.mjs`). 실제 계정에서 다르게 나오면 알려 주세요.

- **언제 갱신되나:** 매일 아침 8시(`src/lib/cloud/config.js`의 `REFRESH_HOUR`). 그 시간에 브라우저가 꺼져 있었으면 켤 때, 팝업·대시보드를 열었을 때 6시간이 지났으면 다시 가져옵니다. **지금 갱신** 버튼도 있습니다.
- **실시간이 아닌 이유:** 세 서비스 모두 청구 데이터를 몇 시간~하루 늦게 집계합니다.
- **월말 예상:** 사용량은 이번 달 누적 ÷ 지난 날 수 × 이번 달 날 수, 요금제 같은 고정비는 그대로 더합니다. 단순 추정입니다.
- **원화:** [open.er-api.com](https://open.er-api.com) 환율(12시간마다)로 바꿉니다. 실패하면 달러 금액만 보입니다.
- **키 보관:** 키·토큰은 `chrome.storage.local`의 `cloudAccounts`에만 있고, 저장소는 확장 페이지·background만 읽을 수 있게(`TRUSTED_CONTEXTS`) 막아 둡니다. 오류 문장에 키가 되비쳐 나오면 가립니다. 화면은 금액만 담긴 `cloudCosts`를 읽습니다. 각 서비스 API 말고는 어디에도 보내지 않습니다. 컴퓨터 자체가 털리면 키도 노출되므로, 반드시 **읽기 전용** 키를 쓰세요.

### Azure 앱 등록 (배포자가 한 번만)

Azure 로그인 버튼을 쓰려면 이 확장을 Microsoft Entra 앱으로 등록해야 합니다. 비밀값은 필요 없습니다.

1. [Azure 포털 → Microsoft Entra ID → 앱 등록](https://portal.azure.com/#view/Microsoft_AAD_RegisteredApps/ApplicationsListBlade) → **새 등록**
   - 이름: `결제 기록장`
   - 지원되는 계정 유형: **모든 조직 디렉터리의 계정 및 개인 Microsoft 계정**
   - 리디렉션 URI: 플랫폼 **공용 클라이언트/네이티브(모바일 및 데스크톱)**, 값 `https://<확장 ID>.chromiumapp.org/azure`
     (확장 ID는 `chrome://extensions`에서 확인. 웹 스토어에 올리면 ID가 바뀌니 그 주소도 추가)
2. **API 사용 권한 → 권한 추가 → Azure Service Management → 위임된 권한 `user_impersonation`**
3. 개요의 **애플리케이션(클라이언트) ID**를 `src/lib/cloud/config.js`의 `AZURE_CLIENT_ID`에 넣습니다.

> 앱을 "모바일 및 데스크톱"으로 등록하는 이유: "단일 페이지 앱"으로 하면 로그인이 24시간마다 풀립니다. 대신 Microsoft가 확장의 `Origin` 헤더를 거절하므로, background의 토큰 요청에서만 `declarativeNetRequest`로 Origin을 지웁니다(웹페이지 요청은 건드리지 않음 — E2E로 확인).

## 무엇을 저장하나

| 저장함 | 저장 안 함 |
|---|---|
| 사이트 도메인, 날짜, 유형(구독/일회성/결제수단 등록), 주기, 금액 | 전체 카드번호, 유효기간, CVC |
| 카드 브랜드 + **끝 4자리** | 페이지 본문 |
| 결제대행사(토스·이니시스·Stripe 등) | 외부 서버로 보내는 데이터 없음 (클라우드 연결 시 각 서비스 API·환율 API만 호출) |

모든 기록은 이 브라우저의 `chrome.storage.local`에만 있습니다. 확장프로그램을 삭제하면 기록도 지워지니 필요하면 CSV로 백업하세요.

## 동작 방식

- `src/content.js`: 모든 페이지·iframe에서 카드번호 입력칸과 결제 버튼 클릭을 감지하고, 페이지 글자에서 금액·주기·구독 여부만 뽑아서 보냅니다.
- `src/background.js`: 탭 단위로 이벤트를 30분 동안 하나의 기록으로 합칩니다. 결제창 팝업이나 PG 리다이렉트도 원래 사이트 기록으로 묶습니다.
- `src/lib/detect.js`: 금액·주기·유형 판별 (할부·날짜 오인 방지 포함)
- `src/lib/ledger.js`: 병합, 월 환산 합계, 다음 결제일, CSV

## 한계

- **보안 키패드**를 쓰는 카드사 결제창은 카드번호를 읽지 못합니다. 기록은 남지만 카드 칸이 비어 있습니다.
- **앱 인증**(카카오페이·토스 앱 푸시, 앱카드) 결제는 실제로 완료됐는지 알 수 없습니다. 결제 버튼을 누른 시점에 기록합니다.
- 판별은 휴리스틱입니다. 틀린 기록은 대시보드에서 **수정**을 누르면 고칠 수 있고, 한 번 수정한 기록은 자동으로 덮어쓰지 않습니다.
- 과거 결제 내역은 없습니다. 이미 등록해둔 자동결제는 [페이인포](https://www.payinfo.or.kr)나 카드사 앱의 정기결제 조회로 확인한 뒤 **직접 추가**로 넣으세요.

## 개발

```bash
npm test                 # 판별·장부 로직 단위 테스트
CHROMIUM_PATH=<chromium 경로> node e2e/extension.e2e.mjs   # 실제 Chromium에 올려 결제 흐름 3개 검증
CHROMIUM_PATH=<chromium 경로> node e2e/cloud.e2e.mjs       # 클라우드 연결·갱신 실패·Origin 규칙 검증 (API는 가짜 응답)
```
