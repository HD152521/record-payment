# 결제 기록장 MVP 구현 계획 (v0.5.0)

작성 2026-11-18. 목표: 기록을 거의 손으로 넣지 않고, 매달 카드별·분류별로 자세히 본다. MVP가 끝나면 웹스토어에 올린다.
기준: `main`에서 새 브랜치 `feat/v0.5-mvp`. MV3, 빌드 없음, 바닐라 JS, `npm test` + Playwright E2E 9개.
조사 근거: 추가 화면(Bobby·Rocket Money·ReSubs 사례), 자동화(Rocket Money=Plaid, 토스=마이데이터 → 서버 없는 구조에선 불가).

공통 규칙: 키·기록은 브라우저에만, 외부 요청 추가 없음(로고 API 금지), 새 권한 추가 없음, 함수 50줄·파일 800줄 이하, console.log 금지, 글씨는 작게(12~14px)·모서리는 기존 토큰(6~12px), 기존 E2E 9개 유지, 데이터 형식 바뀌면 기존 저장값 그대로 읽힘.

## Step 1. 서비스 로고 넣기

Simple Icons(CC0) SVG 중 카탈로그(`src/lib/catalog.js`)에 있는 서비스만 골라 `icons/brands/`에 넣고, 카탈로그 항목에 아이콘 이름과 공식 색을 붙인다. 아이콘이 없는 서비스는 이름에서 만든 색의 글자 아바타를 쓴다(서비스마다 색이 다르게). 라이선스 안내를 README에 적는다.

- Acceptance: 카탈로그 서비스의 아이콘이 있거나 서로 다른 색 아바타가 나온다(단위 테스트) / 외부 이미지 요청 0건(E2E에서 확장 밖 이미지 요청 없음) / zip 크기 증가 300KB 이하
- Out of scope: 외부 로고 API(Google favicon·Brandfetch), 카탈로그 서비스 추가

## Step 2. 빠른 추가 화면 개편

`src/quick-add.js`·`src/sheet.css`의 3열 격자를 한 줄 목록 `[로고] 이름 · 기본 요금제 가격/월 · [✓]`으로 바꾼다. 검색창 고정, 분류는 한 줄 세그먼트(검색 중 숨김), 처음엔 "IT인이 많이 쓰는 것" 8~10개 먼저. 누르면 기본값(흔한 요금제·월간·오늘·자주 쓰는 카드)으로 바로 담기고, 담은 줄만 그 자리에서 펼쳐 요금제·결제일·카드를 바꾼다. 아래 "고른 곳" 칸 대신 "고른 것 N개" 요약, 주 버튼 "N개 추가 · 월 ₩합계", 닫기는 위 ✕. 검색 결과가 없으면 "'검색어' 직접 추가" 줄.

- Acceptance: 이름이 잘리지 않는다(1280·375px 스크린샷) / 하나 누르고 "추가" 한 번으로 저장된다(E2E) / 기존 picker E2E 흐름(여러 개 담기·되돌리기·자세히 입력·AWS는 연결 화면)이 그대로 통과
- Out of scope: 카탈로그 가격 갱신, 새 서비스 추가

## Step 3. 카드별 이번 달 합계와 카드 상세

`L.cardSummary`를 이번 달 기준(나간 돈·나갈 돈, 구독+일회성, 원화 합산 — `src/lib/forecast.js`와 같은 규칙)으로 바꾸고, 카드 화면에서 카드를 누르면 상세(이번 달 금액, 그 카드의 구독·결제 목록, 다음 결제일)를 연다. 카드 미지정 기록은 "카드 안 정한 기록 N개"로 모아 한 번에 카드를 정한다.

- Acceptance: 카드별 이번 달 합계의 합 + 카드 미지정 합계 = 홈의 이번 달 예상에서 서버·API를 뺀 값(단위 테스트) / 카드 상세가 열리고 목록이 맞다(E2E) / 미지정 기록 여러 개를 한 번에 카드 지정(E2E)
- Out of scope: 카드사 연동, 카드 한도·실적 관리

## Step 4. 달마다 그래프 나눠 보기

`src/trends.js`·`src/lib/history.js` 그래프에 "전체 / 카드별 / 분류별(AI·개발 도구·업무 도구·생활 구독·서버·API)" 보기 전환을 넣는다. 계열 색은 dataviz 검증을 통과한 색만 쓰고, 계열이 많으면 상위 4개 + 기타로 묶는다. 막대에 마우스를 올리면 계열별 금액이 나온다.

- Acceptance: 보기마다 달별 합계가 전체 보기와 같다(단위 테스트) / 색 팔레트 검증 스크립트 통과 / 보기 전환이 새로고침 뒤에도 유지(E2E)
- Out of scope: 외부 차트 라이브러리, 엑셀 내보내기

## Step 5. 카드 이용내역 파일 가져오기

설정 또는 추가 화면에서 카드사 이용내역 CSV/엑셀(xlsx는 우선 CSV로 저장해 올리게 안내)을 고르면 브라우저 안에서만 읽어, 같은 가맹점이 비슷한 금액(±10%)으로 매달·매년 2번 이상 반복되는 줄을 구독 후보로 찾고, 카탈로그와 가맹점 이름을 맞춰 서비스명을 붙여 "확인할 기록"(pending)으로 넣는다. 끝 4자리가 있으면 내 카드와 연결한다. 이미 있는 기록과 겹치면 넣지 않는다. 첫 지원은 신한·삼성·현대·KB 양식(샘플은 개인정보를 가린 가짜 파일로 테스트), 모르는 양식은 열 고르기(날짜·가맹점·금액)로 받는다.

- Acceptance: 양식별 가짜 파일에서 반복 결제를 찾는다(단위 테스트) / 겹치는 기록은 다시 넣지 않는다 / 파일 내용이 저장소·네트워크로 나가지 않고 후보만 저장(E2E에서 요청 0건)
- Out of scope: 마이데이터·은행 연동, xlsx 직접 파싱 라이브러리, 실제 사용자 명세서

## Step 6. 구독 계정 페이지에서 읽기

사용자가 서비스의 결제·멤버십 페이지(Netflix, YouTube Premium, Spotify, ChatGPT, Claude, GitHub, Google Play 구독, Apple, 쿠팡 와우, 네이버플러스 중 화면 구조를 확인할 수 있는 곳부터)를 열면 요금제·가격·다음 결제일을 읽어 "결제 기록장에 추가할까요?" 작은 안내를 띄우고, 누르면 "확인할 기록"으로 넣는다. 사이트별 파서는 저장된 HTML 조각 픽스처로 테스트하고, 못 읽으면 조용히 넘어간다. content script는 지금처럼 저장소에 직접 접근하지 않고 background 메시지로만 보낸다.

- Acceptance: 사이트별 픽스처에서 요금제·가격·날짜를 뽑는다(단위 테스트) / 이미 기록된 구독이면 안내를 띄우지 않는다 / 거절하면 그 사이트는 30일 동안 다시 묻지 않는다
- Out of scope: 로그인 자동화, 실제 계정으로 확인, Gmail 영수증 읽기

## Step 7. MVP 마무리 점검

버전 0.5.0, `docs/store-listing.md`·`docs/privacy.html`에 파일 가져오기·계정 페이지 읽기 설명 추가, 스토어 스크린샷 다시 찍기(`e2e/store-shots.e2e.mjs`), `npm test`·E2E 전체·`npm run pack` 보안 점검.

- Acceptance: 테스트·E2E 전부 통과 / 권한 목록 변화 없음 / 처방침과 등록 문안이 새 기능과 어긋나지 않음(store-listing 테스트)
- Out of scope: 웹스토어 제출, 홍보
